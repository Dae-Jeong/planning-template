# __PROJECT_NAME__ Policy Direction (위임 가드레일)

최종 수정: __DATE__

구현 에이전트가 세부 정책 변수나 UX 디테일을 **매번 사람에게 되묻지 않고 직접 확정할 때 따르는 가드레일**입니다.
여기에 적히지 않은 일반 구현 디테일은 아래 "기본 스탠스"를 적용한 뒤 근거를 남깁니다.

## 1. 서비스 전제 (모든 판단의 기준)

- 사용자 유형 / 규모: <!-- 예: 내부 운영자 30명 / B2C 공개 서비스 / 고객사 어드민 등 -->
- 참고 시스템 / 관례: <!-- 예: Slack 관례 / 네이버 예약 관례 / 사내 어드민 표준 -->
- 핵심 우선순위: <!-- 예: 악용 방어보다 사용 마찰 최소화 우선 / 보수적 감사 로그 우선 -->

## 2. 기본 스탠스 (Tier 2/3 위임 영역)

1. 의심되면 정의된 **참고 관례**를 따르고 선택지와 근거를 WP/Decision에 남긴다.
2. 파괴적 동작(삭제 등)은 UI 확인 1회, 데이터는 **보존 우선(soft delete)** 을 기본으로 둔다.
3. 제한값(최대 글자 수, 페이지 크기, 재시도 횟수 등)은 코드에 하드코딩하지 않고 설정/정책 변수로 분리해 시작한다.
4. 사용자 오류 문구는 **행동 중심 한국어**로 작성하고, 내부 스택·DB·벤더 raw error는 노출하지 않는다.

## 3. 영역별 방향 (필요 시 채워서 사용)

| 영역 | 기본 방향 |
| --- | --- |
| 입력 / 검증 | 제어문자 · zero-width · 길이 상한 공통 정규화, 클라이언트+서버 이중 검증 |
| 목록 / 페이징 | URL Search Params 단일 소스, 기본 정렬/페이지 크기 명시 |
| 권한 / 접근 | 최소 권한 원칙, 타 테넌트/비멤버 접근 시 데이터 존재 유무 누설 방지 |
| 실패 / 재시도 | 일시 오류와 영구 오류 분리, 멱등성 키(`Idempotency-Key` 등) 우선 검토 |

## 4. Red Line — 에이전트 단독 확정 금지 (Decision Owner 승인 전용)

아래 6개 항목은 에이전트가 임의로 결정하지 않고 `10-decision.md`의 `__PROJECT_CODE__-OPEN-*` 또는 질문으로 남깁니다:

1. **제품 Scope 변경**: `20-spec.md` v1 In/Out 기능 추가·삭제
2. **인증 · 보안 · 권한 구조 변경**: 토큰 방식, 로그인 흐름, 역할 체계 변경
3. **데이터 영구 삭제 · 보존 기한 · 백업 정책**
4. **외부 노출 변경**: 공개 가입, 비인증 공유 링크, 외부 웹훅 허용 등
5. **비용이 발생하는 기술/인프라 선택**: 유료 SaaS, 관리형 DB, 신규 LLM/API 도입
6. **미결 `OPEN-*` 아키텍처 결정의 임의 확정**

- 가드레일 안에서 확정 가능한 세부 정책은 에이전트가 결정 후 **해당 SPEC 정책 변수 표 + WP/config**에 반영하고 근거를 남깁니다.
